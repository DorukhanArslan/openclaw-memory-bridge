# One-User Native Memory Lifecycle

This fixed acceptance follows one fictional user, Sable, through native memory writes, a preference change, keyword and semantic recall, profile-context loading, flush, compaction, maintenance, and recall after restart. It uses one retained corpus and native parent-linked sessions. The harness writes configuration and evidence; source notes must be written by native agent tools or native maintenance.

Run only for an explicitly authorized current scenario with the configured OpenRouter credential:

```sh
npm run acceptance:one-user
```

The command takes no model, destination, root, or replay arguments. It is not an installation or automatic CI step. A fresh checkout does not establish an unused allowance for historical runs.

## Scenario and evidence

Sable's current profile and canonical preference note are created by the native agent. The initial drink is mint tea; an explicit update changes it to rooibos while preserving the Monday orchid schedule, bicycle transport, and a dated thermometer event. Prior preference history belongs in the dated note. This tests explicit source editing, not unsupported automatic fact supersession.

The same query, `pedal-powered commuting`, must first miss in keyword mode and then retrieve the bicycle source with genuine text-embedding-3-small embeddings. A fresh child session must have empty conversation history, a persisted native navigation parent, and actual saved `USER.md` content represented in native prepared-context metadata.

A unique standing inspection code is then supplied through the official local agent while file-writing tools and flush are disabled. The flush trigger uses the official native Gateway client with server-granted `operator.admin` authority. Native history must attest owner input; request payloads never supply an owner flag. A later native flush must write the code and retain `agent` provenance. Attribution joins the current debug dispatch to its internal flush session and the native artifact-provenance file hash, with no foreground write. The provenance database is read only; no lineage or database rows are manufactured. A successful flush marker alone is insufficient.

Native summarizing compaction must commit. Manual native maintenance must publish light, REM, and deep model diaries without fallback and produce a sourced durable promotion. After Gateway restart, a fresh linked session must recover the current profile and dated/inspection facts from saved sources. The original main session identity must remain intact.

Source dates follow the lab's explicit native UTC timezone. Reports include the actual source day and native session IDs. Navigation parentage is not a trusted supersession contract.

## Finite current-scenario budget

The new scenario has its own stable admission, activation, and request ledger. It does not reuse the consumed small-smoke approval or reconstruct missing historical ledgers.

| Resource | Bound |
| --- | --- |
| Chat attempts | 32 |
| Aggregate chat body bytes | 450,000 |
| Chat body per request | 100,000 bytes |
| Reserved output per request / total | 2,048 / 26,000 tokens |
| Chat framing allowance | 1,024 tokens per attempt |
| Embedding attempts / aggregate body bytes | 64 / 1,000,000 |
| Missing native utility output bound | 1,024 tokens |

The model IDs, endpoint paths, token bounds, rates, and ledger policy are fixed. Published pricing across all advertised tiers is checked before admission. The estimated envelope is 4.88523968 USD; adding the previous small smoke's conservative estimate gives 4.90756672 USD, below the approved 5 USD current-work envelope. These are estimates, not strict account-wide currency reservations or proof of historical cumulative spend.

Every native attempt reserves durable counters before transport. Native retries also consume attempts. Unknown models, destinations, request bodies, ambiguous output limits, and paid hosted tools fail before dispatch. Utility adaptation only adds the explicit finite output limit when the pinned native utility request omits one; it preserves the native model, messages, tools, and memory semantics.

The existing weekly 50 USD quota is retained as current-window evidence. General/cumulative paid gates and all historical lifecycle/maintenance controls remain separate and unchanged.

## Retained artifacts and stop behavior

Everything is retained under the ignored `.lab/one-user-lifecycle/` directory:

- `admission.json` and `activation.json`: exclusive durable consumption records.
- `ledger.json`: reserved counts and any denial reason.
- `preflight.json`: native quota and published-price evidence.
- `report.json`: incremental stages, source snapshots, traces, and final result.
- `corpus/`: the one native workspace, sessions, logs, and indexes.

An existing directory, activation, malformed state, or uncertain attempt denies automatic replay. Preserve these records on success and failure. Do not delete, repair, reset, or rename them to rerun. A stopped run remains partial evidence; stages that did not execute are not passes.

The scenario's temporary native permission is removed during cleanup. Diagnostic files and historical reports are not published or replaced by this command.

The consumed corpus and allowance remain preserved; the correction does not authorize replay or repair of that attempt.
