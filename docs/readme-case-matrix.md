# README promise and behavior coverage matrix

Review proposal. No test removal is approved or performed. This matrix maps behavior, not a percentage of executed lines.

## Test tiers

- **Fresh SDK/engine:** installed Python client plus actual no-key OpenClaw, with temporary files and real process restarts.
- **Current native CI:** real native/CLI checks at published `961cb42`, in [CI run](https://github.com/DorukhanArslan/openclaw-memory-bridge/actions/runs/38198940078). These cases reuse existing executable tests.
- **Protocol/HTTP/config fixture:** tests controlled failures. It does not prove a model capability.
- **Historical model audit:** assertions over retained genuine provider records. Fresh model execution is NOT RUN. Missing records are SKIP.
- **Coverage gap:** NOT TESTED. Never convert a skip, fixture, config flag, or fallback into success.

The full details and exact runner command are in `docs/readme-case-matrix.json`. All fresh SDK cases require Python >=3.10, an installed wheel, and the pinned foundation runtime. The current checks used Python 3.12. No provider key is needed for those cases. Historical model audits require the corresponding local ignored record. A fresh model run needs the existing finite approved flow and the cumulative 5 USD ceiling.

## What is still not covered

Changed-fact supersession is not accepted. Fresh semantic/model generation through the Python SDK is not run. The SDK has no text/embedding selector, chat, flush, compact, or consolidation trigger. Its lifecycle read methods do not prove model generation in the same scope. App note deletion does not test erasure of backups or duplicate captures. Workspace routing does not test authentication.

## Cleanup and assertion rules

Each fresh SDK case uses TemporaryDirectory, closes the owned MemoryClient, and removes its test root. Files, sources, search hits, IDs/routes, restart persistence, and errors are asserted where relevant. The examples create only synthetic input. No case imports unrelated user data. Existing native tests retain their own try/finally cleanup and explicit model gates. Audits read only retained synthetic records. Every matrix row supplies setup, expected assertions, prerequisites/tier, cleanup, and an executable runner.

## Proposal for old-test removal — approval required

**Remove zero tests now.** The new cases make agent behavior easier to see. They do not replace the lower-level failure matrix. A ten-case pass cannot justify removing auth, timeout, UTF-8, size-limit, secret, request-budget, ownership, or filesystem checks.
